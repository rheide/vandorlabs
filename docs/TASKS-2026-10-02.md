# Programmable block improvements

## Requested tasks (verbatim)

Programmable TrapDoor and Programmable Diagonal Trapdoor issues:
- For rotating and sliding trap doors and diagonal trap doors create z flickering when open because they blend into the neighboring block, we should leave 1 minecraft pixel visible.
- Non-diagonal trap doors: I can't seem to place these in the middle alignment when clicking in the world, though that option does work from the dialog.
- V-angled diagonal trapdoors: when I place 4 trapdoors in a 2x2 area, but the bottom and top 2 have different slopes (e.g. leaning south for top, leaning north for bottom), the trapdoors don't connect. We want these to connect if angles are opposite - also for the future door texture enhancement for trapdoors described below).
- For a same-angled 2x2 block of rotating diagonal trapdoors, the top 2 doors seems to rotate outwards (away from the player) and the bottom 2 inwards (towards the player). We should angle both of those in the same direction, preferring the angle that opens towards the top by default. It would be nice if the rotating direction was configurable per block for combined doors, though perhaps unnecessary if we can get it right programmatically.
- When a place two full-height-full-width blocks diagonally (e.g. top block is Z+1 and Y+1 for example), can we consider those to be connected as well for the purpose of diagonal trapdoors? They don't quite connect in the world but I would like to be able to use the same connected-opening behavior and door texture application (future - described below) that we use for two half-width diagonals that are placed directly on top of each other.
- A bit of a vague request: for our Programmable Landing Gear block, I would like to be able to place a trapdoor-like block next to it that can close over the blocks underneath a retracted landing gear block. Currently this is not easily possible because the landing gear reserves the full blocks below it when expanded. I imagine this could sort of work if either a trapdoor was allowed to be placed in the landing gear's expandable area, or if a trapdoor could be placed next to that area, but could open/close outside of its own block boundaries in the direction of the block underneath the landing gear. Add a solution for this and let me know what you decided on.
- Not sure if we're doing this already, but would be nice if we could support stretching the combined door behavior more on a single axes, e.g. allow a combined 2x4 trapdoor or a 5x2 diagonal trapdoor.


Texture list improvements:
- I want Categories for textures. We already have three 'texture packs', and after the door additions (see next item) to the general texture list, I would like to have Categories that are expandable/grouped rows in the texture selection list. Each Category can start collapsed, and we should select the appropriate category and block for each type of block (e.g. Door category for doors, Lights category for lights, Screens category for screens).
- I'd like the door texture to be available as options in the general Programmable Block texture list (that we also use for trap doors). I don't really care about whether we pick top or bottom texture for single blocks, but for connected trapdoor blocks we should be able to use both top/bottom textures automatically. I think it's fine to split the small/medium/large options here out into separate texture entries in the list, though I don't want separate entries for their top/bottom blocks.
- I'd like the screens to be available as general textures in this list in their own Screens category. As with doors, fine to split this out into small/medium/large separate textures for the sizes. It's fine to leave animations out of this for now and keep those configurable only for the programmable screen/console/etc. blocks. Don't add separate list items for each animation frame, just the static first frame is fine.
- For the texture list, it would be lovely if we could have tiny thumbnails to the left of each name. If we can do this, then we can remove the texture preview area and make the list wider.
- Let's also add the Programmable Light textures to this list. I want one unified list for all the blocks, with Categories for the stuff we previously had separate. Programmable Light blocks should be updated to use this list as well (and same for the Wall texture list - another unified list, with built-in thumbnails, we can drop the preview)
- Don't forget to use this unified approach for other Programmable Blocks like consoles/inputs/screens/slabs/stairs/triggger block
- I'd also like to use the new unified texture list for door blocks, since we will have door textures available in that list.


Programmable Light blocks improvements:
- Hotbar icons for Programmable Light Slab and Frame don't look like lights. Fix that and also make sure they fit the hotbar slot and don't overgrow it.
- When placing a Programmable Light Frame at the bottom of a ceiling block, it places at the bottom edge of its block rather than 'attaching' to the block on top of it. Bad. This problem also occurs when placing against a wall block or floor block, it always attaches to the wrong face (near instead of far).
- There's no option to tile/fit the side texture of Programmable Light Slab. This should be a universal setting of all programmable slab blocks we add
- Can we add a Size option similar to Programmable Half Input? If size is smaller the light should align on the center of the block.


Vanilla block loading option:
- I'd like an option to be able to load a vanilla block (or any other mod's block's) texture into our Programmable Block. Following our texture list unification changes, I'd like a "Custom.." option in the list that shows a slot we can drop a minecraft block into, which will put its texture onto the Programmable Block (or whichever other block uses the unified texture list).
- I'd like to also be able to load e.g. vanilla (or non-vanilla) doors into this for Programmable Doors and Programmable Trapdoors (since they all use the unified list)


Misc:
- I noticed Programmable Half Input doesn't have an option either to select fit/tile for its side texture. When we move the side texture to the unified list approach we should also add this option. There might be other programmable screens/consoles/inputs that need this option/generalization, so fix those too.
- Programmable Block textures with transparency: I don't think we currently support this very well? It would be nice if we could dynamically create a block (or slab, or wall) that would look similar to the Programmable Porthole (wall) if parts of the texture were transparent. Report back on this if it's too complex, we can analyze and decide what to do with this later.
- Landing Gear: we've got the Extra Large option which aligns in the center of a 3x3 area, can we also have this aligned on a 2x2 area? I think it's the same size, so maybe we can just change alignment depending on how the user places the block? Otherwise it's fine to introduce a slightly different size for this.
