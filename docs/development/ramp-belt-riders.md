# Native belt rider planning

The horizontal selector consumes immutable actor snapshots, captured source shapes and explicit foreign obstacles. It reuses the same authored whole-assembly belt emitter as cell rendering. Selection preserves Source acquisition tolerances, known-item upward/no-clip exceptions, the strict 0.75-block history anchor radius, lower landing steps, Y/X/Z clearance order, downward floor clipping, side-wall clipping and wrap detachment.

The frozen actual `stepEscalator` corpus contains 13,824 callbacks. Native selection matches all accepted actor positions/bounds, momentum, grounding/fall, saved history, no-clip flags and committed distance bit for bit (763,656 assertions). The accepted changed-state count is 12,012. Entity bounds in the replay use the released float dimensions rather than recovering an imprecise double width by subtracting translated endpoints.

There is a deliberate fail-atomic safety difference: Source changes actor state in 24 of its 84 refused steps and changes history in 12. The native selector returns a refusal without applying its proposed anchors or pruning history. Those Source-only refused mutations are counted explicitly, separately from accepted parity. A world planner must preflight every rider and publication before committing any anchor, movement or history update. Planner/state/reset and actual-world acceptance remain separate work; no public belt runtime is enabled by this selector.

Independent vertical and reset callbacks are frozen in `ramp-belt-transitions-source.jsonl.gz` (41,472 profiles, expanded SHA-256 `fbb85855ddc7b1bfb6c3fe67085f8be493279cb13af7790dadac087453e7d3c0`). They invoke actual vertical belt steps, horizontal rider reset, and the vertical return-to-original dispatch. Native replay compares 2,011,370 scalar fields exactly, including 1,270 refused callbacks. Vertical steps preserve item horizontal velocity and do not update horizontal anchoring history. Horizontal reset returns supported riders to original source surfaces; vertical reset follows original per-step geometry. These are selection/collision references, not journal or live-player acceptance.

`NativeRampBeltRiders.State(operation)` is ephemeral and operation-scoped. `prepare` and `prepareReset` produce same-tick plans; the controller must stage/preflight physical publication, call `recheck`, then `commit`, and only then install `nextDistance`. A stopped deployed belt retains state; configuration/removal uses the reset plan. Cold reserved/query chunks refuse without loading. No elapsed-time catchup occurs, and duplicate successful steps in one tick do not advance distance. `correctionFailures` reports delivery failures after the authoritative batch commits.

History uses at most 8,192 weak entity identities with scalar position values and generation-based expiry. State retains only weak world/profile references and at most 64 packed reserved-chunk coordinates. Unload/explicit reset invalidates outstanding plans. Actors arriving after preflight or changing position/body/velocity/eligibility reject recheck/commit. Item anchor corrections are included in the shared physical batch while support displacement excludes the anchor correction. Physical rollback happens before any external correction callback; network failures do not roll back block ownership.

Private dedicated world check `test_ramp_belt_riders.py` passes 22 assertions with actual Item entities: deferred/noClip/high-upward anchors, actor changes and late arrival, duplicate/stalled tick behavior, horizontal and vertical transport/reset, momentum, worker refusal, and world/state retirement. The runner waits for the actual server PID and final saves before retention. This establishes the planner boundary, not controller integration, real connected-player belt operation, or public Ramp activation; those remain separate acceptance steps.

Private connected-player acceptance (`test_ramp_belt_client.py --xvfb`) passes eight actual Survival stages, 58 server and 170 client assertions, and six real S2C corrections at five server ticks per second. It covers horizontal Player/Item transport, a foreign ceiling refusing the whole reset, clear-and-retry, vertical transport and original-geometry reset, phase wrapping, walking against the belt onto an adjacent upper half-slab landing, deployed-state retention, and fresh-operation history isolation. Both game mode and selected/held inventory are synchronized; loose items have pickup disabled so item acquisition cannot change the fixture's held-tool precondition. Each actor is placed on its own tread support, accounting for different body widths. The unchanged shared rider client receives the actual corrections. This remains private planner/transport acceptance, not public controller scheduling or journal integration.

Final focused headless acceptance adds an explicit reused-numeric-ID/distinct-entity identity negative, worker refusal for resetting bound operation state, reserved/query chunk recheck, and a separate-process vanilla Item save/restart. The full suite passes 25 write and five restart assertions, retaining the exact three-item stack and opaque custom data while restoring no rider history. The fixture keeps its chunk loaded and allows entity storage to settle before shutdown; both phases wait for actual process exit and final saves, including failure paths. Final CPU replay remains 55,296 frozen callbacks and 2,775,026 strict-bit assertions. These checks do not activate public Ramps or substitute for journal/controller integration.
