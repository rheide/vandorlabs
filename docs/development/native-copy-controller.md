# Native Copy Controller transfer adapter

The native Copy Controller is registered by default as `copy_controller`, with its crafting recipe and Vandor Labs creative entry. It uses the shared Programmable Surface block for paired-pad discovery and provides typed configuration and durable material withdrawal. Construction-chip input accepts supported existing designs.

The controller discovers matching filled rectangles on its left and right and uses the physical vanilla chest behind its authored front. The saved layout uses the released Source position packing. Pad ownership is identity checked, holes release both saved areas, and settled controllers do not repeatedly discover their pads. Changes within a dirty component coalesce through deferred identity-checked updates.

A copy recipe derives output cells from an immutable input snapshot, or from a bounded construction-chip design. Channel increments affect documented setting fields after material costs have been calculated. Private inventories contribute exact item and component costs. Resource-bearing block carriers require their complete configured item. Unknown physical ownership is refused rather than priced as an empty block.

Single and double supply chests are represented by their physical halves. A double chest in the source requires both reciprocal halves from the same block type and facing. The output keeps the two physical inventories and the original orientation. Newly installed halves also protect access through vanilla’s combined inventory wrapper until the lease retires. The receipt preserves all non-inventory metadata and records each slot's exact before and after stack. It recomputes the released greedy withdrawal policy when decoding. Publication withdraws those slots before installing output blocks. Recovery accepts only the receipt's exact slot values and never overwrites an unrelated change with a guessed refund.

The cell journal's two disk boundaries revalidate the installed controller, actor, settings, pad claims, input contents and material cost. Read-only reservation checks recognize only the exact callback Header object and its live durable reservation. Raw foreign Ramp and arm reservations remain refused, independently of internal write scopes. This observation grants no write admission; block and slot publication still require the armed exact lease.

The focused server path exercises real asynchronous preparation, exact component-bearing inventory costs, a caught failure immediately after material withdrawal, rollback, retry and physical output installation. The input inventory remains unchanged, the supply pays once, and no loose resource copies appear. It also checks hole repair and zero discovery/packet deltas after the finite twenty-tick activity indication has settled. The family-specific cold path then halts after actual armed withdrawal and an asynchronous save of only the supply chunk across an output chunk boundary. Startup restores the exact original backing items and components, retains the input, leaves output absent, produces no loose copies and retires recovery before gameplay. This is separate from the common engine proof. The Survival client path exercises ordinary interaction and the Configurizer, reverse redstone cycling, height selection, Check areas and Copy. Output blocks and their tile updates are published to observing clients after journal retirement. Run `python3 test_copy_client.py --xvfb --with-jei` from the NeoForge platform directory to check the installed JEI ingredient registry and search alongside that journey. The focus registers the four legacy landing compatibility items and checks that their IDs remain available while the default browser omits them.

Construction-chip decoding is read-only. It does not consume or rewrite the chip. Designs containing unavailable native blocks, including an unconverted Vehicle Controller, are retained and refused. This adapter does not add replacement controllers or a native Vehicle Chip authoring route.

A stationary Navigation Table copy can include one complete filled flat rectangle or one same-facing angled row, up to the native 256-cell layout limit. The decoder verifies each member's connections, settings and relative pointers against the complete layout before and after translation. It refuses a partial group, unresolved ownership, multiple physical chips or modules, and neighboring tables that could join the output. The horizontal output boundary remains held throughout publication.

The original physical chip and module stay in their source cells. Survival requires one table item per section and exact matching configured chip and module components. The translated reader and bay continue to address the same physical slots. The transfer's exact removal scope suppresses table inventory ejection when rollback removes a staged output.

Run `python3 test_copy_client.py --xvfb --joined-navigation-table` from the NeoForge platform directory for a connected two-cell table with one Navigation Chip and a separate Navigation Module. The focus refuses an adjacent table, catches a failure after both output slots are installed, checks exact refunds and no loose items, then retries and reloads the saved world in another server process.

A formed stationary Survey Dish or Sentinel Array can be copied when the scan contains its entire core and reserved frame footprint. Copy checks the same relative part offsets and owner identity as native formation and refuses an incomplete frame, unsettled ownership operation or unknown core metadata. The output receives a distinct identity shared by its own parts. Facing, inversion, size, radar setting and transmission range stay intact. A configured Copy increment shifts transmitted channels through the normal checked channel policy.

Survival pays one matching Core and the number of Programmable Matter Blocks in the actual frame. Interior reservation cells carry no material cost. The focused `python3 test_copy_runtime.py --observers` dedicated run forms an upright Survey Dish and inverted Sentinel Array, rejects partial scans, injects failure after protected output cells are installed, and retries after checking exact refunds. Both copied observers must resolve every part and enter native navigation discovery.

Copy can translate all seven stationary Programmable Screen roles with their saved appearance, facing, frame and local display activation settings. Include the entire joined layout and keep its input and output boundaries loaded and clear of other Screens and credential readers. Copy checks all six faces and the native join lattice, including diagonal rows. Both boundaries are held during publication. The adapter refuses construction-chip Screen templates, embedded credentials, chip and private media modes, channel subscriptions, and configured redstone rows or transmitters. Survival pays one plain matching Screen item per section. Configured item stacks cannot satisfy that cost.

Run `python3 test_copy_runtime.py --screens` from the NeoForge platform directory for a dedicated Survival fixture with pairs of each role, including both diagonal inversions. The fixture also checks the single-member behavior of roles that have no native join. It checks both boundaries, leaves an embedded physical chip untouched after refusal, injects a failure during output publication and checks the exact refund. Retrying must preserve the exact appearance and native group membership. The Console keeps artwork in both of its display slots, and the Input keeps its keyboard and upper mounting properties.

A formed Synthesis Tower, Assembly Press or Enclosed Gantry can be copied from a complete stationary input area. Empty every slot and disconnect the production machine before copying. The adapter verifies the native frame and each reserved part's exact relative owner. It preserves the saved facing, corner, idle recipe selection and activation settings, and allocates a separate owner for the new assembly. A Copy increment shifts its configured channel bank.

Survival pays one plain matching Core and the exact number of Programmable Matter Blocks in the frame. Interior reservations carry no material cost. Drives, unfinished layouts, connected or running production, owned contents and builder templates from construction chips are refused. The dedicated `python3 test_copy_runtime.py --builders` fixture checks real formation, full frame ownership, preservation of a refused source chip, rollback after protected output cells install, and exact costs on retry.
