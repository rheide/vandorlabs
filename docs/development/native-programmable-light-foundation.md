# Native programmable Light foundation

The full, frame and slab Light families have an inactive scalar foundation. It does not register native blocks, items, entities, screens or renderers.

The actual source corpus distinguishes fresh construction from typed loading and records the complete saved tag and configured-item projection for each family. Its 771 settings cases include integer, byte, short, long, fractional numeric, string, compound and array representations. Light-owned fields use `LightData`; inherited housing, channel, frame, artwork and transmission fields retain their existing shared adapters and separate authorities. Lights are excluded from the standalone Screen device-housing default; their fresh housing remains the constructor finish rather than the Screen family default. A positive first saved channel selects the legacy redstone-on trigger only when an integer Light trigger is absent. Invalid integer triggers normalize to manual mode.

A further 66,816 actual-source evaluations cover all three emitted-light implementations. `ProgrammableLightPolicy` keeps configured brightness, direct numeric power, joined numeric power and joined boolean power distinct. Numeric brightness uses the selected signal level plus the clamped offset and ignores both the trigger and saved manual-on value. The manual click path can still change its saved manual-on value when the trigger is disabled. Outside numeric mode, the configured level remains readable even while the light is off; emitted light is zero while off, and lit artwork additionally requires a positive level.

Loaded joining, actual channel/physical sampling and configured-item installation remain separate acceptance boundaries. The source grouping code requires the same block identity, facing and effective face artwork, matching slab half and join eligibility; manual membership also matches current on state. Power reconciliation deliberately groups without that final on-state comparison. Small frame lights remain independent. No eager world scan, new native host or public interaction is introduced by this scalar foundation.

Future propulsion adapters may reuse scalar signal inputs and clamping only after auditing their own source behavior. Particle thresholds, propulsion activation, moving-world authority and Vehicle Mode are outside this foundation. The Light evaluator therefore accepts sampled numeric and boolean inputs and retains no world, tile or channel-service reference.

A separate actual-source grouping corpus freezes 9,722 layouts and callback outcomes over all six facings. It covers manual member selection, power reconciliation, mixed numeric and boolean lights, channel callbacks, different block identities, slab halves, artwork, small frames, unloaded boundaries and invalid/unloading members. The 4,095-member group remains usable; reaching the released 4,096-member scan limit collapses membership to the selected light. Numeric groups publish the maximum sampled level and derive joined boolean power from that level. Boolean-only groups update joined power while preserving their existing saved joined numeric level. The native policy retains no graph, world or tile after a call. Host lifecycle, observer staging and real-player acceptance remain inactive.

The source corpus also records the real configured pick/drop tag separately from duplifier choices. Pick and drop agree and remove joined numeric/boolean power, channel runtime signal and identity/position fields. The native Light-only item projection excludes its joined runtime fields; shared item adapters remain responsible for inherited choices and owned modules. A 144-case interaction corpus preserves main/off-hand consumption, creative sneaking configuration, survival sneaking pass-through and server-only manual writes. These policies do not open a native menu or register an item.

Forge now delegates Light-owned save fields and brightness/activation evaluation to the same portable codec and policy as the native foundation. The actual source settings, interaction, signal and joining corpora retain their hashes. The adapter preserves lazy input reads, including zero direct queries for manual and already-joined lights; legacy live joined values remain saveable and normalize on load. The focused Forge lighting path covers six facings, single/joined Porthole and Logo artwork, front/back visibility and reversed draw order. The inactive native host below is integrated; renderer, editor and public registration remain separate work.

The inactive housing adapter now freezes 72 actual-source geometry profiles: full, frame and slab, all six facings, both slab halves and both raw small-input values. Only frame Lights honor the small-input flag. The native one-box cache is fixed at 72 entries and accounts for less than 1 MiB of retained shape storage. Each family preserves zero opacity and full ambient brightness. None gains contained-fluid support. Vertical slab faces retain a horizontal half-height housing rather than rotating the half into a wall.

An unregistered native host composes the shared housing, frame, glazing, playback, channel and transmission codecs with Light-owned choices. It uses the generic constructor defaults, without the standalone Screen factory. Main transmission choices remain saved but Lights publish no channel output. Unknown or occupied reader/control/module representations and future native schemas stay inert with their original tag retained for saving. Public model data contains only an immutable visual projection; opaque capability, fluid and ownership data stays private.
