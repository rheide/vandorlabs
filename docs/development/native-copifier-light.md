# Programmable Light copied settings

The inactive native Light adapter is grounded in the released `ProgrammableSettings.capture` and `apply` callbacks. The Java 8 `exportCopifierLightSourceReference` task freezes 2,919 bounded memory-world observations: 384 capture/full-copy cases, 2,376 partial edits, 48 cross-role copies, 108 conflicting layout/legacy-flag transitions and three joined-sibling probes. All full, frame and slab metadata values are represented. The compressed reference is `testclient/fixtures/copifier-light-source.jsonl.gz`; its expanded SHA-256 is `5405c04f776651e6c6f7a92c0d77993db410ec7731f11d7632a1ebb34e4aeb13` (8,549,518 bytes).

Capture resolves the automatic front artwork into the legacy housing/light index. Apply preserves typed-field distinctions, validates the complete transmission/layout contract before mutation, applies the legacy side flag before the explicit layout, changes the trigger before attempting manual ON/OFF, and changes only the selected leaf's manual setting. Frame-only small mode and copied frame artwork version follow the actual setters. Clipboard data and block metadata remain unchanged. Malformed recognized values may be applicable without changing settings; they must not be normalized into unrelated defaults.

These observations invoke actual Source callbacks and tile serialization with a simulated world. They establish callback ordering and saved-field semantics, not packet authorization, real-player behavior or native world acceptance. Deferred registrations and world caches are retired through their actual unload callbacks after each observation. Native installed-owner, channel publication, opaque-data and restart checks remain separate acceptance requirements. Public Copifier dispatch remains unchanged.
