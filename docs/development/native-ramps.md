# Native standalone Ramps

The conversion keeps standalone Ramp Controllers, their Slab variant and generated controlled-ramp cells in scope. Vehicle adapters remain deferred. Existing portable `RampControllerData`, `RampCellData`, `ControllerPlatform`, `RampGeometry`, `RampAxis` and `VerticalRampGeometry` provide scalar persistence, bounded platform discovery and motion geometry. They do not replace the controller's snapshot/journal ownership protocol.

## Source settings and item baseline

`exportRampSettingsSourceReference` freezes 256 actual Source observations: both controller roles, all sixteen metadata inputs, fresh factory defaults and seven saved-data profiles. Each observation calls the real tile reader/writer, `ProgrammableSettings.capture`, configured pick and block bounding box. The expanded `ramp-settings-source.jsonl.gz` is 468464 bytes, SHA-256 `4b3b9c540e4aab2ecadcb3137024bba3c424bac1ddd9a8edbb7b8f98c97412e7`. This is a fixed-clock memory-world callback fixture; it does not establish real placement, mining, generation, journal durability or player authorization. No platform or generated cell is transferred.

The registry IDs are `programmable_ramp` and `programmable_ramp_slab`, sharing tile identity `programmable_ramp`; generated cells use `controlled_ramp`. Full-controller metadata preserves horizontal faces and active bits plus vertical scan faces. Slab metadata encodes six scan faces and two halves; activity is derived from the tile. Its body remains horizontal half height for every scan face. Scan direction and horizontal travel direction are distinct, including UP/DOWN placement.

Fresh factory state and reading an empty saved compound differ. Existing scalar migration also normalizes old LEFT travel by reversing offsets into RIGHT travel. Half-step endpoints, interpolation, escalator, vertical-layout and moat settings supplement `RampControllerData`; native settings must compose those fields rather than silently dropping them. Configured pick writes a private `RampSettings` choice compound, excluding captured blocks and journal state. Actual placement consumes that compound through `configureHalfOffsets` and then applies channels, so configuration refusal and gameplay activation refusal must be distinguished. Copied settings use the same configuration callback. The channel footer is independently applicable; Ramp Controllers are not supported transmitters, so a Transmission-only descriptor is ignored.

## Ownership boundary

Native generation and public activation remain unimplemented. A future host must keep `onLoad` local, defer registration and recovery until installed identity is confirmed, preserve unknown or failed snapshot envelopes inert, and refuse unsupported ownership-bearing state. No active captured platform may be normalized into choices or released before durable recovery. Journal publication must reuse `JournalFiles` and prove asynchronous completion, abrupt restart and partial-save ownership separately from these scalar fixtures.

`exportRampCallbacksSourceReference` adds 640 actual `ProgrammableSettings.apply` calls and 160 actual `onBlockPlacedBy` callbacks using configured picks, across both roles and every metadata input. Its expanded reference is 2613626 bytes, SHA-256 `b471d189a5d2a971b7df6c80cbea8c13f5a1673bf05e5d5a50d645b377f14d03`. Each callback asserts the input is unchanged and that no sources/cells were acquired. 96 copied callbacks return false after changing captured settings: configuration may commit before the empty-platform activation fails. Invalid configuration can also leave its error/status result while a later channel footer remains independently applicable. Transmission-only edits are ignored because these controllers are not supported transmitter slots. A native transaction must reproduce that distinction rather than equating a false gameplay result with an atomic settings refusal.

These callbacks use the real Source implementation with a permissive memory-world player and no platform. They do not establish WorldServer action receipts, authenticated packets, durable capture/recovery, real placement consumption or live mining. Those paths require focused placed-world and journal tests before activation. Every snapshot now asserts that the queried world owner is the exact tile being serialized and that its position matches the installed cell. Saved-data profiles restore world coordinates before reading. This catches mismatches between factory-created world tiles and separately constructed test objects.

## Native typed choices

`NativeRampSettings` composes the existing portable `RampControllerData` reader with the Source half-step, LEFT-to-RIGHT, interpolation, escalator and layout migrations. It represents choices only: no captured block, tile inventory, journal, authorization receipt or active timeline is exposed. Its capture and configured-item projections match all 256 installed Source observations through `testRampSettingsReference`. Factory defaults remain separate from reading an empty saved compound. Slab half/scan state stays outside the choice value, and a missing configured horizontal direction resolves against the block's horizontal facing. No native block, entity, menu or runtime is registered by this checkpoint.

## Inactive host foundation

`NativeRampEntity` keeps the full and Slab roles distinct and publishes immutable choices plus received/physical input scalars. Its load queue and `onLoad` are local; loaded registration and `queueInputRefresh` use the existing deferred channel service and `NativeLoadedRedstonePower`. It declares no wireless output. No native production block, item, editor, renderer, generation or activation route is installed. In particular, this host has no successful configuration/runtime API that could bypass the future journal transaction. The Source half-height housing and metadata remain requirements for the later block adapter.

Only settings-only snapshots are installed. Captured sources/cells/source tiles, pending recovery, active motion, original non-air blocks, unknown AIR payloads, future schemas, external capabilities and owned/opaque transmitter modules are retained as one exact inert snapshot. Public updates contain only the known choice/input projection. Valid platform fields are decoded through the shared guarded component/attachment loader and removed from private retention after success; deleting live components or persistent data cannot resurrect stale originals. Unknown component maps remain inert and survive restart. Old packed journal coordinates remain private and untouched; a future native link schema must explicitly distinguish them.

## Configuration admission and activation

`RampConfigurationPolicy` freezes Source's validation order independently of world mutation. Vertical-layout/mode/interpolation checks precede actor admission; direction, travel, speed, half-step bounds and supported tread sizes follow it. A valid request normalizes escalator start and vertical-layout travel direction before choice installation. Its transaction interface requires old ownership recovery before committing choices, then invokes activation. `PENDING` is distinct from refusal in both phases: pending old recovery leaves choices unchanged; pending or refused activation preserves the already committed choices. No production transaction/generation implementation is supplied by this policy.

`NativeRampConfiguration` adapts copied fields with Source's exact tag-type rules and configured items with their different direct-getter rules. Partial copied edits fall back through whole-block offsets, so existing odd half steps can change even when the edited field is unrelated. Configured placement applies channels after the configuration callback even if it refuses. Ramp Controllers receive channels but do not support transmitter slots; a Transmission-only edit is ignored.

The independent admission corpus contains 9,408 actual Source calls across both roles, all metadata, three current-choice profiles, nearby/distant/connected-copy/edit-denied/spectator/client-side/absent actors and fourteen edits. Its expanded reference is 33,322,660 bytes, SHA-256 `5a133c29471f458f39e913c7472c7fa63a0b66e8b4850184140a6b8a790a7656`. Native replay matches the actual configuration revision, final choices, validation errors and independent channel footer. There are 808 admitted commits followed by a false callback result and 64 admitted commits whose visible choices are unchanged. The original 640 copied and 160 configured-placement callbacks remain separate regression inputs. The executor's nine synthetic recovery/activation combinations establish ordering only; neither they nor the memory-world actors establish real action receipts, generation or durable recovery. The host and public bindings remain inactive.

## Private durable before-image bridge

`NativeRampJournal` is Ramp-specific. The server thread validates installed ownership, all affected edit claims, loaded chunks and supported tile round trips before copying the before image. Preparation leaves sources usable. A separately durable ARMED record precedes source quiescence and proxy publication. Workers receive copied NBT/path data, use a bounded executor/byte budget, sync the regular file, atomically publish it and sync newly created directory entries through `JournalFiles`. Records, cells and retained memory are bounded; unsupported records remain on disk. Native coordinates are explicit X/Y/Z fields, distinct from legacy packed Ramp links.

Caught partial publication and abrupt restart use the same before images and operation nonces. Recovery never overwrites an unrelated owner or loads a cold cell. Original tile data is staged before publication and checked for lossless round trip. The initial supported tile boundary is vanilla Chest/Barrel and non-inert native Storage; other tiles refuse before source removal. This is a journal boundary, not permission for the future material-discovery adapter to accept every one of those blocks. Inventory contents are cleared only after durable arming, preventing ordinary container removal from ejecting another owner.

Retirement snapshots one affected loaded chunk per main-thread step, enqueues `ChunkMap.write` immediately, then waits asynchronously for `IOWorker.synchronize(true)` through the narrow accessor. It does not mark chunks clean, so later ordinary edits remain dirty and later queued saves cannot be overwritten by delayed old snapshots. A failed write/synchronization keeps the journal. This bridge currently rolls back interrupted capture to original blocks; it does not yet resume a deployed Ramp timeline.

`test_ramp_journal.py` passes eight actual dedicated processes covering a real pending disk gate, source usability during preparation, post-fsync I/O refusal, caught partial proxy publication, normal completion/restart, an abrupt halt with exactly one affected chunk saved, and an actual closed-region I/O failure followed by restart recovery. A newer unrelated queued chunk save survives reload. Every completed recovery has one usable diamond inventory with unchanged opaque source fields and no ejected copies. Normal shutdown and abrupt halt are separate phases; the abrupt fixture disables ordinary saving only after proxy publication and explicitly flushes one chunk to make the partial-save layout deterministic. All runtimes finalize retention after their final restart.

The committed bridge is still private: player/automation/explosion gates around held/restoring sources, existing-open-menu handling, functional Ramp generation/geometry and public bindings are required before activation. In particular, the current held-cell index is an ownership signal, not yet a global interaction or automation gate.

## Canopy close seam

`NativeRampReservations.prepareClose(ServerLevel, canopyRoot, channels, conservativeArea, SweepQuery)` exposes READY/PENDING/REFUSED plus blocked cells and partner roots. `SweepQuery.readiness()` is consulted only after loaded candidates exist. It reuses `NativeLoadedTileIndex`, follows only loaded part owners, checks actual published physical bounds, and queues no forced recovery. Settings-only roots have no owned cells; unresolved active geometry or Moat paths remain PENDING and inert ownership refuses. `bindChanged` is a retry-position notification seam, not a synchronous neighbor callback.

The private journal fixture proves empty-index clear admission without a sweep, pending-sweep waiting and physical proxy blockers/clearance. Those are actual static ownership proxies, not a claim of moved-Ramp/Moat collision parity. Real motion must publish the immutable reservation view before the active Moat positive path can be accepted. No READY fallback is supplied for missing runtime geometry.

### Prepared cancellation boundary

A durable PREPARED record does not imply that source ownership moved. Preparation leaves the original containers usable; interrupted preparation retires its journal without replaying old before-images. Only an ARMED record loaded after a restart is treated as potentially mutated and requires world recovery. In-process failures before publication likewise cancel without replacing legitimate source edits. Retirement remains asynchronous and retains the operation until file deletion completes.

The focused two-process `prepared-edit` journal case edits an original chest after durable preparation, transfers one of seven diamonds into a separate chest, explicitly flushes the changed chunk, and halts before arming. Restart preserves the six-plus-one distribution and retires the PREPARED record. This establishes the cancellation boundary independently of partial-publication recovery; it does not establish held-owner protection or functional Ramp generation.

### Frozen stationary source owners

The private journal freezes affected source coordinates only after before-image and authorization revalidation, immediately before the asynchronous ARM write. Preparation remains usable. A main-thread mutation scope identifies the exact operation; it cannot bypass another operation's cells. Held positions remain protected through restored-container checkpointing and asynchronous journal retirement. Canopy reservation checks treat that publication interval as PENDING.

The held snapshot stores weak world/container references and immutable positions. Ordinary worlds without a frozen Ramp take an empty fast path. Hopper discovery refuses held cells and combined-container wrappers; standard NeoForge inventory-wrapper insertion, extraction and replacement refuse held owners. Existing source menus close before the final revalidation. The Level guard rejects replacement and destruction before loot, with scoped interaction, break, explosion and drop-event filters as additional entry guards. Unknown handlers are not implicitly supported. Unopened vanilla loot containers and linked chests refuse capture before ownership transfer; ordinary single Chest/Barrel and the native Storage container remain the initial tile boundary.

Checkpoint polls do not repeatedly serialize every source while merely waiting for disk futures. Before-images are checked at chunk-publication boundaries and again before retirement. The retained cell list shares its private NBT with the journal record; worker publication receives a separate immutable copy. Per-cell accounting includes held-position and weak-reference storage.

The dedicated fixture exercises a blocked ARM write, real chest and native Storage handlers, a combined wrapper, hopper lookup, Level replacement/destruction, game-mode break, direct loot publication and an actual explosion. Menu closure uses a server ChestMenu attached to the fixture player; it is not evidence of a network-opened menu. Player-facing generation, movement and public bindings remain separate prerequisites.

Fresh checkpoint-failure recovery also covers native Storage's engine-added envelope. Journal comparisons treat only exact byte-zero `keepPacked` and an empty compound `NeoForgeData` as equivalent to absence, without modifying either retained before-image. Nonzero/wrong-type packed fields and nonempty/wrong-type persistent data remain distinct. The fixture contains explicit refusal controls for those distinctions. Held journals also prevent Canopy clearance when controller/part indices are empty; tile-index absence alone cannot establish that a restored ownership transfer has retired.

This establishes released geometry/ordering and refusal behavior for the recorded layouts. It does not provide physical-player authorization, durable journal or abrupt-restart evidence; those remain native placed-world checks. The immutable native choices include `analogDeployment` for the released Redstone-page control and saved `RampAnalogDeployment` flag. ### Recovery admission before gameplay

`ServerStartingEvent`, after levels/registries exist and before `ServerStartedEvent` and normal server ticking, admits existing Ramp journals. A missing recovery root takes the startup fast path. Otherwise bounded parsing runs on the existing journal worker; the server thread installs exact held coordinates before allowing startup to continue. Unavailable/invalid recovery or a bounded startup timeout fails startup explicitly and retains the journals. This is not a gameplay-wide mutation guard, and pending runtime disk work still remains pending rather than rejected activation.

The restored-source abrupt fixture flushes original Chest/Storage contents and an ordinary block with no tile marker while leaving its ARMED journal unretired. Without admission, the fresh process reproduced destruction of that ordinary source before loading recovery. The fixed fresh process refuses destruction, hopper discovery and the custom inventory-handler mutation before its first normal fixture tick, then retires recovery normally. A separate unavailable-directory case proves explicit startup refusal and unchanged recovery-path data. Directory inspection no longer treats genuine I/O errors as an empty journal directory.

### Common building before-images and contained fluids

Lossless before-image staging now admits the exact native programmable Block, Slab and Stairs families in addition to the private container protocol. Other programmable tile families, linked structures and external item/fluid/energy handlers remain refused. Known owned reader/module envelopes, opaque legacy capabilities and nonempty external attachments refuse before mutation; the original live snapshot is unchanged. Staging enforces its byte budget incrementally before detached load/copy work, with a conservative worker-copy reservation rather than an operation that can wait forever for an impossible reservation.

A held-cell refusal at `NativeFluidWorld.set` closes direct bucket/dispenser and sponge mutation paths. Its empty-held-set path performs no world discovery and leaves unrelated hosts unchanged. The actual wet-slab negative reproduced direct bucket drainage during ARMING without the guard. Fixed focused checks cover held drainage/fill/sponge refusal, unrelated fluid write/drain controls, common-building opaque metadata, contained-water restoration, unsupported ownership and oversize refusal, plus abrupt restart after original buildings have been restored but the journal is not retired. These are capture/recovery primitives; the gameplay material-discovery predicate and moving-part publication still belong to the functional controller.

### World-free moving-part geometry

`NativeRampGeometry` consumes immutable cell scalars and bounded source cuboids, reusing the portable ramp, vertical and current Moat geometry. Its output retains local clipped boxes, origin/step association and source displacement scalars for later material rendering. It contains no level, tile, inventory or raw NBT references. Work/piece limits fail explicitly before publication; retained-byte estimates include referenced origin/shape data, and no unbounded pose cache is introduced.

The native Java 21 checker matches all 9,322 actual generated-part snapshots and 15,596 boxes from the 768-profile released Java 8 corpus, in source order, with zero differing coordinate components in this corpus. It also checks explicit complex-work refusal. This covers ordinary/lift/sideways/filled/vertical/current-Moat primitives and the captured straight-stair shapes; it does not yet establish native placed-world motion, escalator belts, rider carrying, or all independent stair-shape acquisition cases.
