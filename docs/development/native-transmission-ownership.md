# Native development-module ownership

`NativeTransmissionMigration` shares the released development-module upgrade used by Screen-derived hosts. Supported obsolete transmitter items become saved channel/range settings; it does not install an item inventory or activate deferred family behavior. The caller must install the complete staged result or keep the original snapshot inert.

Module envelopes are checked before treating a nonpositive count as empty. A zero-count record can still contain opaque capability or future ownership data. Such records, unsupported item fields and malformed module/tag envelopes are refused, with the complete original available through `unchanged()`. Capability data is not traversed or decoded. A supported, bare empty module retains the released normalization behavior.

The zero-count opaque case fails before this guard and passes afterward. `testNativeScreenTransmission` also preserves the existing 210 Source-normalization profiles and SHA-256 `ffdca89a78e6b2eb8ca88cd54303b15fdd99e3e22b89b58266f3691ee0016ab5`, with additional positive/zero-count opaque and malformed-envelope refusal checks. These are pure staged-policy checks; family placed-world, recovery and public activation checks remain separate.

The outer `VandorTransmitters` inventory must also have its released compound type when present. An explicit wrong-type negative previously passed as an ordinary private field; it now refuses installation while preserving the original. The existing 210-profile normalization hash is unchanged.
