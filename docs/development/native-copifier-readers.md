# Standalone credential reader copied settings

`exportCopifierReaderSourceReference` freezes actual released `ProgrammableSettings.capture/apply` callbacks for both standalone Card and Data Chip readers. The 3,028 observations include 256 full copies across all metadata/factory/saved profiles and 2,772 partial edits. Expanded `testclient/fixtures/copifier-reader-source.jsonl.gz` is 7,071,698 bytes, SHA-256 `fb55a743e731e84c9f714eb0e35a867fcf838f70535258d6b8489a4a3b575bcc`.

Reader copying uses the inherited mounted-control branch. It copies mount, rotation and output transmission settings; it does not copy company filters, reader behavior, inserted credentials or return ownership. The token-slot override ignores the requested ACTIVE value and refreshes actual reader output, so a copied switch cannot manufacture credential authorization. For output-only readers, the transmission channels take precedence over the generic channel key. Missing mount fields read as zero, invalid complete triples retain the old mount, and unversioned tilt follows the shared migration policy.

Every Source observation asserts unchanged private reader fields before/after, including the physical stack, pending return UUID, insertion sequence/start, pulse/toggle state, behavior and filter. The clipboard excludes those fields. Source input includes authorized/rejected/opposite-kind credentials and pending-return modes. These are actual callbacks in a memory world with a fixed clock, not packet authorization, actual player inventory transfer or native restart acceptance. Deferred/channel state is retired through actual unload callbacks. Embedded Door/Screen readers, Vehicle and public Copifier dispatch remain outside this adapter.
