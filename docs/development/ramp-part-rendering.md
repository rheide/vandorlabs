# Native Ramp Part client presentation

The generated-part host retains authoritative collision and processed belt timing. Its renderer consumes immutable part publications, with no original tile NBT, inventories or render-time world discovery. Ramp public activation remains separate from this client adapter.

`RampPartAnimation` uses the shared linear `ControllerPlatform.pose` rate and a pause-aware local visual clock. An operation starts from its observed pose and belt phase. New movement commands retarget the current cosmetic pose continuously; duplicate or older revisions do not restart it. A new stationary command installs its authoritative endpoint. Running belt speed/direction changes preserve the current cosmetic phase; a new stop installs the authoritative processed phase so stationary treads match their host. Duplicate stops and late old running commands cannot restart motion.

The focused scalar fixture passes on Java 8 and Java 21, including delayed observations, low server update frequency, reversals, pause/resume, time rewind, late stops and final endpoints. Its warmed 100,000-sample batch allocates zero bytes. This establishes only the scalar clock policy; placed-host rendering, material reload and moving mesh costs require their separate focused client checks.

The native clock cache is keyed by weak world identity, controller position and operation UUID. Equal operation identity retains progress through host replacement; a fresh operation starts from its own observation. Every generated cell in an assembly shares that scalar clock; per-cell geometry and materials stay separate. This avoids phase resets when many generated cells are visible. Values contain no level or block-entity references. Conservative retained accounting limits each world's scalar cache to 256 KiB, and world unload retires it. The native cache fixture checks isolation, replacement, operation reset, eviction and retirement; warmed 100,000 lookups allocate zero bytes. Atlas-dependent presentations remain a separate cache and must all retire on resource completion.

The inactive block-entity adapter captures source sprites and biome tint only when immutable source/material bindings change. Stationary draws reuse their prepared geometry and vertex arrays. Moving geometry is rebuilt only when the local sampled pose or belt phase changes; repeated draws within one frame reuse it. Adapter retention counts source/material/spec bindings, generated geometry and prepared vertices conservatively under a separate 8 MiB per-world budget. The existing mesh backend retains its own independent bounded cache. Every adapter entry is cleared on completed atlas reload, including parts that are no longer visible; world unload also clears its entries. Compilation alone does not establish placed-client or moving-build performance acceptance.

## Focused placed-client acceptance

The private world binds ten real `NativeRampPartBlock`/`NativeRampPartEntity` hosts, including one outside the camera. It covers vanilla fallback, configured faces, programmable stairs, glass, slab, ordinary/belt/vertical/Moat/extension geometry. Source opacity-zero properties and settled owner sky light are checked before capture. Actual BE packet encoding and installed-client dispatch cover ordered controls, newer physical phase observations, duplicate/old observations, reversal, late processed stops, same-operation entity replacement, fresh operations and late members sharing one controller clock. A stale component packet exposed the need to wrap the complete vanilla component load; the same negative passes after the host's outer packet/update-tag admission guard.

The completed native atlas/shader/dispatcher focus passes 38 packet assertions and the placed-world checks. Disabling the actual renderer changes 43,020 pixels; resource reload and restoring motion endpoints each produce zero changed pixels. All unseen presentations retire during the reload callback. The stationary warmed adapter and bounds path emits 393,216 vertices over 4,096 calls with zero allocation and no new meshes.

The moving preparation measurement intentionally counts fresh clipped geometry and vertex preparation, rather than presenting cached emission as moving-build cost. Across 62 frames, the ordinary fixture allocates 1,177,400 bytes in total (20,144 peak per frame); the belt fixture allocates 4,143,264 bytes (69,920 peak). Observed preparation CPU totals are 7.3 ms and 9.7 ms respectively across those batches. Current adapter retention is 84,896 bytes and backend retention stays below 1.3 MiB, within their independent 8 MiB budgets. These are bounded fixture and software-rendering measurements, not hardware FPS or arbitrary-density guarantees. Controller scheduling, durable runtime ownership and public Ramp activation remain separate acceptance work.

The generated surface's highlight uses one prepared outer bound, independently of the detailed physical/ray shape. The client handler checks only the loaded target chunk and exact Part block/entity type; missing or inert publications are skipped. It neither enumerates component edges nor creates a per-frame shape union.
