# Native Ramp Part client presentation

The generated-part host retains authoritative collision and processed belt timing. Its renderer consumes immutable part publications, with no original tile NBT, inventories or render-time world discovery. Ramp public activation remains separate from this client adapter.

`RampPartAnimation` uses the shared linear `ControllerPlatform.pose` rate and a pause-aware local visual clock. An operation starts from its observed pose and belt phase. New movement commands retarget the current cosmetic pose continuously; duplicate or older revisions do not restart it. A new stationary command installs its authoritative endpoint. Running belt speed/direction changes preserve the current cosmetic phase; a new stop installs the authoritative processed phase so stationary treads match their host. Duplicate stops and late old running commands cannot restart motion.

The focused scalar fixture passes on Java 8 and Java 21, including delayed observations, low server update frequency, reversals, pause/resume, time rewind, late stops and final endpoints. Its warmed 100,000-sample batch allocates zero bytes. This establishes only the scalar clock policy; placed-host rendering, material reload and moving mesh costs require their separate focused client checks.

The native clock cache is keyed by weak world identity, block position and operation UUID. Equal operation identity retains progress through host replacement; a fresh operation starts from its own observation. Values contain no level or block-entity references. Conservative retained accounting limits each world's scalar cache to 256 KiB, and world unload retires it. The native cache fixture checks isolation, replacement, operation reset, eviction and retirement; warmed 100,000 lookups allocate zero bytes. Atlas-dependent presentations remain a separate cache and must all retire on resource completion.

The inactive block-entity adapter captures source sprites and biome tint only when immutable source/material bindings change. Stationary draws reuse their prepared geometry and vertex arrays. Moving geometry is rebuilt only when the local sampled pose or belt phase changes; repeated draws within one frame reuse it. Adapter retention counts source/material/spec bindings, generated geometry and prepared vertices conservatively under a separate 8 MiB per-world budget. The existing mesh backend retains its own independent bounded cache. Every adapter entry is cleared on completed atlas reload, including parts that are no longer visible; world unload also clears its entries. Compilation alone does not establish placed-client or moving-build performance acceptance.
