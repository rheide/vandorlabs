# Copied-settings crafting

Both platforms use `CopiedSettingsRecipeSlots` for shapeless admission: one tool and one eligible input, with every additional nonempty slot refused. The recipe consumes one input through the normal crafting container and returns an independent copy of the complete tool. Clipboard option masks apply before item conversion. The native recipe and serializer remain privately registered for acceptance checks; public activation is pending the remaining item adapters.

The released recipe reference contains 6,076 actual calls across 29 non-Vehicle block families, all sixteen item metadata values, partial existing settings, valid and invalid copied fields, masked options, every two-slot ordering in both crafting sizes, and all 256 four-slot empty/tool/input/other combinations. Its expanded SHA-256 is `acdab7ca97641eca086ae384002d20553df960e534d9b0909e3a4ed539cbddc8`. Complete outputs and tool remainders remain identical after the shared admission extraction. The exact standard Forge JAR passes the live Duplifier focus, including the registered player inventory crafting container's ordinary pickup and quick-move paths: seventeen inputs become exactly seventeen configured blocks, with the complete tool retained. Dedicated-server linkage also passes.

The first native converters cover the nine building housings, using the same typed edit plans as world copying. An absent item settings envelope uses the family's constructor defaults; a supplied partial legacy envelope uses load defaults for omitted fields, matching the released recipe. Outer private item data remains with the output and native block-entity components take precedence over legacy custom-data fields. No clipboard field is loaded as a whole block entity. The private dedicated-server recipe focus passes 2,152 cases and 25,070 assertions against the independent released outputs, including masks, exact output count, complete independent tool remainders, cropped crafting inputs and unchanged original stacks. Other item converters, actual native crafting-container interactions and public registration remain separate acceptance work.

Full, Frame and Slab Light item conversions now reuse their existing world-copy plans through the same recipe. The expanded dedicated focus passes 2,728 cases against the released recipe, comparing all captured Light choices as well as applicability, tool remainders and unchanged input envelopes. This does not add public recipe or tool registration.

Ordinary and Large Door generic item settings extend that replay to 3,112 cases. The output includes the dedicated door placement envelope and copied channels. Inputs already carrying a dedicated door envelope or credential-recovery envelope remain refused until their separate precedence and ownership checks pass. This intermediate adapter is still private.

Dedicated configured-input precedence, recovery refusal and actual crafted-item placement still require their own expanded acceptance before activation.

Eight separate 64 KiB ownership negatives verify refusal and complete input/tool retention.

All seven Screen roles extend recipe acceptance to 4,840 Source cases. Actual configured-chip ownership and crafted placement checks remain part of the final private recipe acceptance.

Existing linked-world or recovery snapshots are refused intact. The existing Trapdoor copied-settings plan supplies ordered layout/core/channel handling, and its item writer supplies the resulting configured choices.

Eligibility for world copying does not imply eligibility for the released crafting recipe. Configured-input expansions, Segmented Doors, Canopies and Ramps remain separate recipe acceptance work.

The configured-input reference contains 8,256 actual Source calls across 43 families, four metadata samples, four plain/generic/dedicated/conflicting input envelopes and twelve clipboard edits. Its expanded SHA-256 is `75c0ea5505d6b06a2f3af20e7bd00640d7c2334ea2289ccfd9d822eaca083d55`. The existing 6,076-case reference remains byte-identical. Native replay currently passes all 5,760 configured cases for registered families, including Segmented Doors; the 2,496 Canopy/Ramp cases await their public registrations and item adapters.

Configured copying applies typed writers to a complete retained input copy, so clearing optional frame/playback fields removes old values instead of resurrecting them through a later compound merge. Door dedicated envelopes override generic choices and supply their own channel fallback. Empty physical reader projections track the resulting security choices; physical credential/recovery owners remain refused. Screen item copying follows the Source world-free callback: valid row edits keep their configuration but disable active rows because the unplaced tile has no supported block slot, and its stored row capacity is eight. Installed-world copying retains the family's normal enabled-slot and four/eight-row rules. These contexts share the same ordered edit implementation through explicit item/world entry points.

This pure comparison does not establish held-tool, connected/Undo or actual item dispatch, which remain pending their integration checks.
