# Copied-settings crafting

Both platforms use `CopiedSettingsRecipeSlots` for shapeless admission: one tool and one eligible input, with every additional nonempty slot refused. The recipe consumes one input through the normal crafting container and returns an independent copy of the complete tool. Clipboard option masks apply before item conversion. The native recipe and serializer remain privately registered for acceptance checks; public activation is pending the remaining item adapters.

The released recipe reference contains 6,076 actual calls across 29 non-Vehicle block families, all sixteen item metadata values, partial existing settings, valid and invalid copied fields, masked options, every two-slot ordering in both crafting sizes, and all 256 four-slot empty/tool/input/other combinations. Its expanded SHA-256 is `acdab7ca97641eca086ae384002d20553df960e534d9b0909e3a4ed539cbddc8`. Complete outputs and tool remainders remain identical after the shared admission extraction. The exact standard Forge JAR passes the live Duplifier focus, including the registered player inventory crafting container's ordinary pickup and quick-move paths: seventeen inputs become exactly seventeen configured blocks, with the complete tool retained. Dedicated-server linkage also passes.

The first native converters cover the nine building housings, using the same typed edit plans as world copying. An absent item settings envelope uses the family's constructor defaults; a supplied partial legacy envelope uses load defaults for omitted fields, matching the released recipe. Outer private item data remains with the output and native block-entity components take precedence over legacy custom-data fields. No clipboard field is loaded as a whole block entity. The private dedicated-server recipe focus passes 2,152 cases and 25,070 assertions against the independent released outputs, including masks, exact output count, complete independent tool remainders, cropped crafting inputs and unchanged original stacks. Other item converters, actual native crafting-container interactions and public registration remain separate acceptance work.

Full, Frame and Slab Light item conversions now reuse their existing world-copy plans through the same recipe. The expanded dedicated focus passes 2,728 cases against the released recipe, comparing all captured Light choices as well as applicability, tool remainders and unchanged input envelopes. This does not add public recipe or tool registration.

Ordinary and Large Door generic item settings extend that replay to 3,112 cases. The recipe deliberately does not run the installed-world legacy model migration: the released crafting callback has no world, so partial old door tags retain their decoded motion settings. The output includes the dedicated door placement envelope and copied channels. Inputs already carrying a dedicated door envelope or credential-recovery envelope remain refused until their separate precedence and ownership checks pass. This intermediate adapter is still private.

Ordinary Glass extends the dedicated replay to 3,304 cases, including exact comparison of the resulting dedicated glass item envelope. Normal configured picks and recipe outputs now use one envelope writer. The crafting adapter preserves the input's panel facing and generic playback while applying dedicated outer choices; the placement adapter retains its separate placer-facing behavior. Dedicated configured-input precedence, recovery refusal and actual crafted-item placement still require their own expanded acceptance before activation.
