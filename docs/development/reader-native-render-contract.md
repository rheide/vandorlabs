# Native reader render boundary

`NativeReaderAssets` retains the released card/chip frame models and standard source artwork. The generator preserves all 24 face/rotation variants and eight square sprites without substituting a generic holder. The native atlas source publishes these resources when reader or Door rendering is active.

`NativeReaderRenderer.Bake` prepares immutable frame meshes from the actual native model bake. Hosts supply their existing pose and render layer. Standalone readers and Door security panels use the same frame and contents backend; the Door caller applies its established half-scale panel transforms. Contents accept only the bounded public visual/motion projection. Canonical credential icons remain private, bounded by kind and company, and never expose the owned reader inventory.

The shared `ReaderVisualMesh` retains the released face bases, logo winding, rejection mark, two indicator strips and smooth insertion/return offset. Empty readers display their configured company logo; rejection temporarily replaces it with the amber mark. An unknown occupied credential has no invented fallback icon. `NativeReaderVisualClock` keys cosmetic state by world, owner position and slot, retains motion across immutable snapshot or tile replacement, and deduplicates repeated insertion/rejection updates. Its pause-aware clock does not compare client world time with server start timestamps. Transport must publish the accepted coherent snapshot before rendering.

Focused verification separates source emission, actual resources and actual drawing. `testReaderVisualMesh` compares actual Forge overlay records, logo records and item matrices on every face/rotation. `testNativeReaderClock` covers repeated updates, local expiry, new insertion sequences, owner-position replacement, world unload and pause/resume. The title-only resource check compares all actual native frame faces and every uploaded sprite RGBA byte. The separate title rendering fixture asserts card/chip frames, rejection marks, indicators and visible canonical credential items and retains its rendered image. These checks do not establish placed-reader interaction or the complete Door world renderer.

The inactive standalone mounted-model adapter also preserves the two authored item models. Its focused Source corpus covers 3,072 world poses and 128 configured item variants, including the reader-specific NORTH item pose and support-plane offset. The native title fixture compares these meshes and authored GUI transforms before and after resource reload, then measures every rendered inventory icon for visible padding. This is a model acceptance boundary; placed tile model-data publication, contents rendering and player interactions require their own world fixture before canonical activation. Resource-pack override delegation remains a separate compatibility check.

Reader item preparation retains at most 128 weak component identities and 64 pose models per wrapper. Components are decoded on misses; warm resolution does not copy NBT. Quad meshes share the generation's 16 MiB weighted cache, and item wrappers retain only weak fast-path references to those meshes. Other mounted families retain their established caches.

Reader removal is a terminal host transition before extracting the owned credential. Its private projection may still clear for observers, while block-state publication, new interactions and output scheduling are disabled. This prevents the cached ON state from restoring the old reader during vanilla removal. The actual occupied-removal check requires air, no remaining block entity and exactly one physical credential drop.

`NativeCredentialReaderRenderer` draws contents only, using the shared pause-aware reader clock and fixed-cardinality mount matrices derived from the same mounted geometry transform. The terrain model owns the frame/pedestal. Its private client/server fixture exercises actual survival BlockItem placement, insertion, empty-hand return, survival-sneak configuration and Configurizer configuration for both reader kinds; mounted world captures accompany those checks. The captures are positive drawing evidence, not a pixel-negative/culling matrix or canonical activation proof. Container, automation and resource-pack replacement checks remain separate activation prerequisites.

The released inventory boundary is a one-slot `IInventory`, with a limit of one credential. The frozen source corpus executes 25,344 direct inventory/Forge `InvWrapper` operations and 320 actual `TileEntityHopper.update()` profiles. Stay modes permit authorized insertion; return modes refuse automation insertion, and a borrowed credential remains locked against actual extraction. The original wrapper nevertheless reports a simulated extraction for a locked occupied slot, so simulation alone is not an ownership transfer. The reader declares no built-in item-handler capability; ordinary hoppers use the inventory fallback. Foreign attached capabilities remain subject to opaque ownership retention.
