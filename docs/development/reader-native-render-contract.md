# Native reader render boundary

`NativeReaderAssets` retains the released card/chip frame models and standard source artwork. The generator preserves all 24 face/rotation variants and eight square sprites without substituting a generic holder. The native atlas source publishes these resources when reader or Door rendering is active.

`NativeReaderRenderer.Bake` prepares immutable frame meshes from the actual native model bake. Hosts supply their existing pose and render layer. Door security panels and screen trays use this frame bake; standalone readers emit the same authored frames through the mounted terrain model. All hosts share the contents backend, and the Door caller applies its established half-scale panel transforms. Contents accept only the bounded public visual/motion projection. Canonical credential icons remain private, bounded by kind and company, and never expose the owned reader inventory.

The shared `ReaderVisualMesh` retains the released face bases, logo winding, rejection mark, two indicator strips and smooth insertion/return offset. Empty readers display their configured company logo; rejection temporarily replaces it with the amber mark. An unknown occupied credential has no invented fallback icon. `NativeReaderVisualClock` keys cosmetic state by world, owner position and slot, retains motion across immutable snapshot or tile replacement, and deduplicates repeated insertion/rejection updates. Its pause-aware clock does not compare client world time with server start timestamps. Transport must publish the accepted coherent snapshot before rendering.

Focused verification separates source emission, actual resources and actual drawing. `testReaderVisualMesh` compares actual Forge overlay records, logo records and item matrices on every face/rotation. `testNativeReaderClock` covers repeated updates, local expiry, new insertion sequences, owner-position replacement, world unload and pause/resume. The title-only resource check compares all actual native frame faces and every uploaded sprite RGBA byte. The separate title rendering fixture asserts card/chip frames, rejection marks, indicators and visible canonical credential items and retains its rendered image. These checks do not establish placed-reader interaction or the complete Door world renderer.

The inactive standalone mounted-model adapter also preserves the two authored item models. Its focused Source corpus covers 3,072 world poses and 128 configured item variants, including the reader-specific NORTH item pose and support-plane offset. The native title fixture compares these meshes and authored GUI transforms before and after resource reload, then measures every rendered inventory icon for visible padding. This is a model acceptance boundary; placed tile model-data publication, contents rendering and player interactions require their own world fixture before canonical activation. The separate replacement-pack fixture verifies configured override delegation, active item/blockstate choices and geometry preservation.

Reader item preparation retains at most 128 weak component identities and 64 pose models per wrapper. Components are decoded on misses; warm resolution does not copy NBT. Quad meshes share the generation's 16 MiB weighted cache, and item wrappers retain only weak fast-path references to those meshes. Other mounted families retain their established caches.

Reader removal is a terminal host transition before extracting the owned credential. Its private projection may still clear for observers, while block-state publication, new interactions and output scheduling are disabled. This prevents the cached ON state from restoring the old reader during vanilla removal. The actual occupied-removal check requires air, no remaining block entity and exactly one physical credential drop.

`NativeCredentialReaderRenderer` draws contents only, using the shared pause-aware reader clock and fixed-cardinality mount matrices derived from the same mounted geometry transform. The terrain model owns the frame/pedestal. Its private client/server fixture exercises actual survival BlockItem placement, insertion, empty-hand return, survival-sneak configuration and Configurizer configuration for both reader kinds; mounted world captures accompany those checks. Paired contents-disabled captures verify that the dynamic contents draw while the terrain frame remains visible. These private captures do not establish canonical activation or an exhaustive frustum-culling matrix; the separate Container, automation and replacement-pack checks cover their own boundaries.

The released inventory boundary is a one-slot `IInventory`, with a limit of one credential. The frozen source corpus executes 25,344 direct inventory/Forge `InvWrapper` operations and 320 actual `TileEntityHopper.update()` profiles. Stay modes permit authorized insertion; return modes refuse automation insertion, and a borrowed credential remains locked against actual extraction. The original wrapper nevertheless reports a simulated extraction for a locked occupied slot, so simulation alone is not an ownership transfer. The reader declares no built-in item-handler capability; ordinary hoppers use the inventory fallback. Foreign attached capabilities remain subject to opaque ownership retention.

The inactive native host implements `Container` through the owned credential service. Mutation requires the installed server-thread host, and client projections expose no physical stack. The adapter preserves source copying/clamping, whole-slot decrement, empty-slot pulse clearing and returning locks; opaque failed ownership cannot be cleared through automation. The dedicated fixture compares the complete inventory/wrapper corpus and invokes the real native hopper ticker for the 320 source profiles using valid supported mounts. Geometry, editor, item placement and saved restart phases remain in the same retained suite lifetime.

Configured reader items delegate authored model overrides only when the source mount compound is valid, including a flat mount. Bare or malformed choices retain the original model. Bake correction requires matching active inherited geometry and state definitions; listed pack models take precedence over private fixture fallbacks. A bounded weak override table avoids retaining arbitrary replacement owners, while default items keep their fixed pose table. Replacement models retain authored held transforms. Oversized flat icons receive native GUI-only fitting, and pack removal restores the original generation's exact source behavior. The focused client checks all 128 default and oversized replacement icons, real predicate overrides, 72 released handoff profiles and resource reload/restoration; default warm model resolution and quad reads remain allocation-free.

The standalone contents renderer reuses a guarded scratch pose while leaving the caller's affine and normal matrices unchanged. Logo lookup reads the current atlas directly, avoiding a transient function object without retaining stale reload resources. The actual connected-client probe measured approximately 168 bytes per empty draw before these changes and zero bytes across three batches of 40,000 flat/mounted card/chip draws afterward. It also checks actual client ray selection, synchronized sneak/tool transitions, single-token removal and contents-disabled pixel negatives for both reader kinds. These are allocation and focused software-rendering measurements, not hardware FPS or shader-pack acceptance.
