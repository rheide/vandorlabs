# Native Trapdoor foundation

Regular and diagonal Trapdoors have an inactive native host foundation. No public block, item, menu or renderer binding is registered by this foundation. Loaded outside-cell collision discovery is connected to the native engine, while the owner/hand interaction transport awaits family registration.

The lifecycle comparison corpus comes from the current Forge tile implementations. It covers reciprocal pairs, legacy squares and ordered assemblies, including missing and unloaded members, incompatible settings, duplicate members, the released 64-member load limit, covers, all triggers and local/channel power. Native relation repair and saved power flags match those source results. Metadata updates stage every member before loaded-only shape notifications, preventing a blanket vanilla neighbor walk from loading a cold linked chunk. The actual native-host fixture separately compares resolved hinge, travel, cover overhang, diagonal opening direction, closed direction and lift against every loaded, source-resolvable profile. Source-corrupt mixed-family relations that fail diagonal pose resolution remain inert with their original saved data.

The coordinate marker `NativeTrapdoorLinks=1` distinguishes modern packed positions from released packed positions; it is independent of the released `TrapdoorSchema`. Legacy positions use the shared legacy coordinate adapter. Unknown native coordinate markers fail closed and retain the original snapshot for the next save. Configured items and public visual updates exclude world links, power bookkeeping and opaque saved data. Public visual updates include offset eligibility as a boolean, so paired clients retain the correct controls without receiving private link coordinates.

Group configuration authorizes every resolved loaded member before changing any choices. Each member's immutable settings, pose, artwork bounds and frame contacts are prepared before publishing dirty notifications, block-state updates or packets. The diagonal band boundary clears the old group relations, while explicit hinge and rotation choices apply only to the selected leaf. Load and `onLoad` prepare only local state; loaded repair, physical input and channel registration run later after identity checks.

Collision publication retains the complete exact source AABB slices in `NativeTrapdoorGeometry`. The block housing publishes only its own unit-cell intersection. That local voxel union uses vanilla coordinate-merging semantics, a balanced merge and a checked retained-byte budget; a separate 4 MiB cache includes the retained geometry cost. Missing or inert hosts use the same clipped union cache and a fixed set of fallback geometry snapshots with a checked 2 MiB budget. Repeated open-diagonal fallback queries therefore reuse a prepared shape. It avoids repeated union optimization and decomposition when publishing a detailed diagonal endpoint. The outside-cell cache publishes separate prepared shapes instead of forming a Cartesian union of the diagonal slices. Dedicated checks cover twenty-four rotating, sliding and cover configurations through the engine collision path, lazy replacement/removal and exact ray discovery. The normal server interaction path additionally checks wire bounds, stale owners, both hands, reach and nearer terrain; manual group permissions use the actual clicked face. Public activation still requires source-matched placement and assembly discovery, contained-fluid and configured-item adapters, renderer binding and canonical player/client acceptance. Passing the controller fixture does not establish those remaining paths.

The dedicated fixture runs a complete save/restart sequence for linked old-world data, physical power, authorization, staged observer visibility, client projection reconstruction, failed-load retention and loaded-link repair. Its enclosing runner finalizes artifact retention after both processes. These focused development checks do not replace the deferred full release gate.

The separate fluid geometry corpus freezes 3,072 actual endpoint profiles, including small and far coordinates, current physical solids and 2,408,972 resulting fluid cells. Another 98,304 cases freeze own-stack, opposite-water and six-face ambient-water precedence. Native comparisons preserve the released signed-zero and float-normalization arithmetic. Fluid faces stay deferred; these comparisons establish the physical volume and opening policy; the full fluid mesh remains a separate acceptance boundary.

The inactive contained-fluid host uses those planes and volumes with stationary saved slots. A dry host prepares only its separating plane; resolved stored or borrowed fluid triggers compact-volume preparation. Explicit buckets and dominant-normal-side placement capture preserve source slot selection. Opening water is derived for contacts and rendering and never becomes saved ownership or a vanilla water outlet. The focused actual-host fixture exercises the normal use-intent/GameMode bucket path, sponge absorption, tagged and unresolved fluid data, future slot/envelope representations, legacy water migration, emitted light, cosmetic cache reuse and a separate-process save/restart. A complete empty envelope after edits suppresses the old `Waterlogged` alias. Opaque source envelopes survive untouched saves and edits to another slot. Public updates contain known stacks or occupancy markers and exclude private envelope fields.

The prepared dedicated editor reuses the shared material picker, programmable dialog layout and regular/diagonal option rules. Native widget checks cover reverse cycling, remembered diagonal width/height, disabled rotating options while sliding, last-valid channel banks, wheel/scrollbar drag, resize and resource reload. Server menu checks retain installed tile identity, current window, distance and Configurizer permissions before the host authorizes the group. Ordinary configuration and Configurizer use share one entry point; no generic redstone dialog substitutes for the dedicated editor.
The final-surface comparison separately freezes the actual opening branch of `WaterloggedSurfaceMesh`, which uses closed separating half-spaces rather than physical voxel faces. Its 27 distinct closed planes cover 5,184 open/closed, same/different tagged fluid, native-water, opaque-neighbor and contained-neighbor cases at small and far coordinates. All 39,280 final polygons match native vertex bits, normal bits and emission order, including neighbor subtraction and liquid corner heights. The common analytic descriptor prepares at most two convex regions and fourteen candidate surfaces and never requests a Cartesian volume face graph. Host integration and rendered wet acceptance remain separate from this scalar comparison.

Trapdoor hosts publish the analytic descriptor during owning-thread fluid preparation. Repeated fluid reads return the same immutable descriptor while plane, open state, resolved fluid identity and components remain unchanged. Same-fluid open sides form one continuous region; unknown occupied slots contribute no visible fluid. A focused actual-host save/restart run also checks repeated preparation of a detailed wet diagonal owner without materializing physical volume faces. The larger 71,710-cell small-coordinate physical case remains covered by the source volume corpus. Rendered wet acceptance is still required before activation.

Specialized native items retain the regular three click bands and diagonal clicked-plane mode, hinge and rotation inheritance. Configured partial tags merge against a fresh tile's item fields; only choices enter a new owner, never saved relations, power or contained-fluid envelopes. Formation follows the released neighbor priority, complete squares, bounded rectangular discovery and half-size connected patches. Channel changes retain their logical power-evaluation order, while immutable member projections publish after the complete formation phase. Removal clears relations before configured harvest metadata is read, including the released cached-facing distinction from a pre-removal pick.

Stationary configured items share one staging/consumption/rollback transaction. Failed rollback retains an inert native owner before consuming its corresponding item. Protected staging/restoration overrides remain available to fault fixtures. Canonical registrations and rendered player acceptance remain separate from the inactive item/formation foundation.
