# Native Trapdoor foundation

Regular and diagonal Trapdoors have an inactive native host foundation. No public block, item, menu or renderer binding is registered by this foundation. Loaded outside-cell collision discovery is connected to the native engine, while the owner/hand interaction transport awaits family registration.

The lifecycle comparison corpus comes from the current Forge tile implementations. It covers reciprocal pairs, legacy squares and ordered assemblies, including missing and unloaded members, incompatible settings, duplicate members, the released 64-member load limit, covers, all triggers and local/channel power. Native relation repair and saved power flags match those source results. Metadata updates stage every member before loaded-only shape notifications, preventing a blanket vanilla neighbor walk from loading a cold linked chunk. The actual native-host fixture separately compares resolved hinge, travel, cover overhang, diagonal opening direction, closed direction and lift against every loaded, source-resolvable profile. Source-corrupt mixed-family relations that fail diagonal pose resolution remain inert with their original saved data.

The coordinate marker `NativeTrapdoorLinks=1` distinguishes modern packed positions from released packed positions; it is independent of the released `TrapdoorSchema`. Legacy positions use the shared legacy coordinate adapter. Unknown native coordinate markers fail closed and retain the original snapshot for the next save. Configured items and public visual updates exclude world links, power bookkeeping and opaque saved data. Public visual updates include offset eligibility as a boolean, so paired clients retain the correct controls without receiving private link coordinates.

Group configuration authorizes every resolved loaded member before changing any choices. Each member's immutable settings, pose, artwork bounds and frame contacts are prepared before publishing dirty notifications, block-state updates or packets. The diagonal band boundary clears the old group relations, while explicit hinge and rotation choices apply only to the selected leaf. Load and `onLoad` prepare only local state; loaded repair, physical input and channel registration run later after identity checks.

Collision publication retains the complete exact source AABB slices in `NativeTrapdoorGeometry`. The block housing publishes only its own unit-cell intersection. That local voxel union uses vanilla coordinate-merging semantics, a balanced merge and a checked retained-byte budget; a separate 4 MiB cache includes the retained geometry cost. Missing or inert hosts use the same clipped union cache and a fixed set of fallback geometry snapshots with a checked 2 MiB budget. Repeated open-diagonal fallback queries therefore reuse a prepared shape. It avoids repeated union optimization and decomposition when publishing a detailed diagonal endpoint. The outside-cell cache publishes separate prepared shapes instead of forming a Cartesian union of the diagonal slices. Dedicated checks cover twenty-four rotating, sliding and cover configurations through the engine collision path, lazy replacement/removal and exact ray discovery. The normal server interaction path additionally checks wire bounds, stale owners, both hands, reach and nearer terrain; manual group permissions use the actual clicked face. Public activation still requires source-matched placement and assembly discovery, contained-fluid and configured-item adapters, renderer binding and canonical player/client acceptance. Passing the controller fixture does not establish those remaining paths.

The dedicated fixture runs a complete save/restart sequence for linked old-world data, physical power, authorization, staged observer visibility, client projection reconstruction, failed-load retention and loaded-link repair. Its enclosing runner finalizes artifact retention after both processes. These focused development checks do not replace the deferred full release gate.

These comparisons establish physical volume and opening policy independently of the analytic final-surface and wet-client checks below.
