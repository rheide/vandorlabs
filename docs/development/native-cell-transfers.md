# Native cell transfer foundation

`NativeCellTransactions` supplies private durable publication for typed family adapters. It does not enable Copy Controllers, Turntable Controllers or Vehicle Mode by itself. Existing arm and Ramp journals retain their own protocols and authority.

A family registers an identifier, snapshot limits and an immutable recipe decoder. It owns actor and controller authorization, supported tile types, known field migrations, opaque-data comparison and its exact publication rules. Requests contain ordered before/after snapshots with identical cell coverage and an explicit held footprint. A request cannot publish outside that footprint. Recipes never come directly from a client snapshot packet.

An explicitly registered `MaintenanceFamily` may submit a server-only maintenance operation without a player. Its records carry a typed maintenance marker and the reserved zero actor UUID; player submissions cannot enter this route, and ordinary families cannot load maintenance records. The family must repeatedly verify its persistent physical owner identity and exact migration eligibility. This authority has no C2S entry point and does not grant a general permission bypass. Unmarked previous player records retain their original format.

Preparation writes copied records on the bounded `JournalWorker`. While those bytes are pending, the request remains queued and does not reserve the source. After durable preparation, the server revalidates its sources and acquires an exact reservation. That reservation protects blocks and physical inventories while the ARMED record is written, but it cannot authorize a write. Source removal, withdrawal and publication begin only after ARMED completes.

`NativeTransferHolds` admits one explicit position write at a time. A callback cannot reuse a consumed admission. Inventory automation remains blocked during internal block writes; physical material slots use a separate receipt that checks the exact container identity, slot and before/after stack. Families must explicitly validate any permitted partial slot state during recovery. Equal block types alone do not establish ownership.

`NativeTransferCheckpoint` takes at most one chunk snapshot per poll and waits for the actual region write futures and flush. It compares ownership before and after durability rather than repeatedly serializing every tile while disk work is pending. Families with actor or entity ownership must provide their own additional receipt, comparison and durable checkpoint. Only then can APPLIED or ROLLED_BACK be published and the journal durably retired. Reservations remain held through completion and cancellation.

Families can return false from `readyAdditional` while native actor sections load. This preserves the pending phase and exact reservation, admits no mutation, and avoids probing entity ownership before loading has completed. Readiness also gates post-installation checkpoints, commit and retirement, including recognized APPLIED records recovered at startup. An unmutated PREPARED cancellation does not wait for actor data that it never owned.

The read-only `escrowState` query checks the registered family, operation, controller, owner, actor and typed receipt. PENDING keeps the family-owned escrow suspended; CONFLICT retains it for diagnosis. ABSENT means that a successful journal scan found no matching operation, and does not by itself authorize release: the family must validate its persisted marker and checkpoint protocol.

Before the first server tick, entity-region reads may await `EntityStorage`'s deserializer mailbox, whose normal executor is the server thread blocked in startup recovery. A pending entity checkpoint polls at most one task from that specific native mailbox before draining the entity manager inbox, and only when its dispatcher is the current server. It does not run the general server task queue, recursively drain the mailbox or replace raw entity-region data. After startup, normal native ticks perform this work.

The separate native arm and Ramp journals also retain inventory holds during their own publication callbacks. Their operation scopes identify the transfer; only a one-use position token around the immediate native block write admits replacement. Callback automation and nested writes cannot reuse that grant. Read-only restoration preflight excludes only the exact owning operation without opening a write scope.

Native entity checkpoints retain the actual entity-region write futures as well as the final flush. A family can validate a copied, byte-bounded native record before its write: harvest custody requires each expected drop UUID, item, position and escrow marker, or absence during rollback. Ramp custody requires each nonplayer participant at its intended position with its item contents intact, while players retain their separate physical-file receipt. Missing or duplicated actors, including an actor omitted by a failing native save callback, prevent completion. Unknown saved drop-escrow markers remain inert and retain their original data instead of throwing during entity admission or becoming usable.

Snapshots, records, recipes, positions, operation counts and retained memory are bounded. World access remains on the server thread. Unloaded chunks and disabled saving suspend progress. Unknown factories, changed owners and I/O failures retain the recovery record; no blind refund is performed. Startup recovery resolves recognized records before gameplay and preserves unavailable records on failure.

The shared Java 8 `JournalPublication` helper syncs file bytes, verifies the written bytes, atomically publishes and routes directory sync through `JournalFiles`. Windows avoids unsupported directory channels; genuine Linux I/O failures remain visible. Disk jobs contain immutable records and paths, never a world or live inventory.

`NativeRawCell` stages unpublished tiles against their physical level and position before guarded deserialization. The factory identity, supported type and caller-owned field comparison are checked before publication. Public moving-block appearance is separately allowlisted by `NativeSnapshotAppearance`; inventories, claims and capability envelopes are excluded. The palette helper retains the five-argument model-data path, while caching, transforms, shading and gameplay authority remain with each renderer.

The focused core checks compare appearance against an independent accepted projection implementation and cover old Surface coordinate packing. The cell-journal focus exercises real pending disk work, reservation, disabled saving, reentrant write rejection, caught partial installation, exact rollback and retry. The separate cold-recovery focus halts abruptly after a real ARMED source-cell removal and an asynchronous save of only the source chunk. Restart restores one usable source inventory with its exact item components, leaves the unpublished destination empty and retires recovery before gameplay. The actor-readiness extension additionally exercises real native entity-section loading while cells stay unchanged and writes remain blocked, both before installation and after rollback/commit. Its restart phases cover ARMED rollback and already durable APPLIED retirement. An unrelated queued server-task sentinel remains untouched during startup recovery. Each production family must additionally prove its own material, actor and ownership receipts on this path.

Construction-chip decoding remains separate from Vehicle Mode. A Source Vehicle Chip can contain unavailable native blocks such as `vehicle_controller`; those designs must be retained and refused without consuming materials or altering the chip. The transfer foundation does not authorize replacement blocks, driving controls or a new construction-authoring mechanism.

The moving visual palette is shared with the existing native arm renderer. It retains the same layer order, complete baked vertex records, sprites, tint/normal flags, ModelData and fallback byte budgets, without calling visual tile onLoad or loading private inventories. An independent copy of the accepted pre-refactor arm algorithm compares actual emitted records across six-face cropped/non-square Surface artwork and the existing housing, storage, rack, sign and chest visual types. Both atlas generations pass 2,354 checks; the real arm payload journey also passes placement, capture, privacy, reload, endpoint restoration and late/reordered update checks after delegation. This proves the shared visual primitive; each new moving controller still needs its own runtime and ownership acceptance.
