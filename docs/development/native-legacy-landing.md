# Native legacy telescopic landing gear

The private 1.21.1 compatibility adapter retains `landing_gear`, `ski_landing_gear`, `landing_strut` and `angled_landing_strut`. These retired IDs have no creative entries or new recipes. The adapter is disabled by default while the ordinary migration entry point and player path are completed. It does not add Vehicle Mode or Taxi behavior.

The permanent physical mount owns its configured item and UUID. Reserved cells carry only that owner's identity and bounded relative offset. A helper cannot become a second usable drop, and mining requires a loaded, validated owner. Size and target changes preflight the complete loaded footprint before changing helpers. A refused publication restores exact previous cells; a failed rollback retains the original snapshot in an inert recovery envelope. Reload preserves that envelope rather than resuming a partially repaired mechanism.

Missing AIR helpers and matching stray helpers are reconciled through deferred, identity-checked updates. Foreign blocks and opaque helper data are never overwritten. Chunk watchers use weak references, fixed limits and unload cleanup; neither onLoad nor collision access forces neighboring chunks. Ski columns cache their lowest loaded controller and publish a position/UUID hint for the matching client dialog.

Java 8 shared policies preserve the released settings defaults, float motion step, reservation ordering, cleanup predicate, piston dimensions and Ski end-connection rule. Native collision uses the authored cuboids and cached exact per-cell unions. Rendering reuses the supplied model bodies and canonical sprites; piston UVs repeat with length, and cosmetic interpolation uses a pause-aware client clock. The stationary fallback remains distinct from modular arm ownership.

Focused dedicated-server checks cover actual Survival placement, retained supports, all six selected small/large family layouts, motion, reversal, foreign-block refusal and retry, configured helper mining, opaque data and cold recovery. The independent policy check compares against the released loops. These fallback checks do not establish the pending player/render path.

The explicit wheeled-conversion request uses a separate typed maintenance family and pure modular after-image preparation. Its decoder proves the complete original Legacy ownership closure, every modular destination field and the exact compatible native neighbors; no unrelated scan-volume cells become reserved. Both original and shifted mounting supports are rechecked without acquiring ownership of them. Common holds pause original Legacy and modular gameplay callbacks until durable retirement.

Focused server checks exercise real pending preparation, disabled saving, a Large source shifted across a chunk boundary, complete feet, compatible native-neighbor opaque data, deployment and reversal. An abrupt halt after durable ARMED intent and saving only the source chunk is followed by original-owner recovery, exact saved fields, a new conversion and reversal. Only typed false `keepPacked` and an empty `NeoForgeData` storage envelope are ignored by metadata comparison; true/wrong-type hints and opaque capability data remain refused for pristine conversion. The player-facing automatic entry point is not yet enabled. Legacy inventory and dropped stacks remain intact until their separate physical inventory/entity receipts are accepted.

The modular destination builder prepares immutable cell images without publishing them. Its world-free validator checks all horizontal facings, regular/Large widths, column heights and both endpoints, including complete feet and legacy-packed owner offsets. Compatible native neighbors retain their opaque envelopes. Unknown or forged owner fields are refused; the destination builder grants no mutation authority. Focused native checks cover 64 profiles, compatible-neighbor preservation and malformed-recipe rejection. The destination builder alone does not authorize existing-item conversion or create a player inventory receipt.
