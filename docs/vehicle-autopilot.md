# Autopilot and waypoints

Mount one Autopilot on the bottom of a vehicle. Navigation uses the same forward direction as manual driving, determined by the Pilot Seat used to assemble the craft. Rotating the Autopilot block does not reverse the craft. Right-click it or use the Configurizer to configure it. Choose the route block from the inventory sample picker; the selected block variant is retained. The default marker is white concrete.

Build a continuous line of face-adjacent marker blocks on the ground, replacing selected markers with Waypoint Blocks. Routes support horizontal corners. Branches and gaps stop and disable the autopilot; it never guesses a branch. The first solid ground block below the controller must be a route marker or waypoint, with no more than 16 empty blocks between controller and ground. Unloaded terrain is not loaded by navigation. Starting travel prefers a marker ahead of the Pilot Seat. If none is ahead, it can follow one unambiguous side continuation at a corner; equally plausible choices stop instead of guessing. It does not reverse automatically at an endpoint.

For diagonal travel, lay a staircase of face-adjacent markers. Autopilot uses a longer lookahead on repeating diagonal stair-steps to reduce heading wobble, while ordinary 90-degree corners retain their shorter lookahead. Its sensor continues along the exact marker line. Lookahead does not skip waypoint stops or choose a branch at a junction.

Select the Autopilot's optional channels and its activation behavior: On, Off, or Disabled. A pulse starts a journey and stays latched until a waypoint. A continuously active signal passes waypoints. Disabling the trigger only disables redstone activation; the Vehicle Status screen can still toggle the autopilot. While enabled, the autopilot owns movement and continues after the pilot exits. Activating a craft parked as blocks inspects and assembles it through the normal protected transfer queue without requiring anyone in a seat. This requires a Vehicle Controller, valid gear and propulsion, and the controller or seat owner online in the same dimension. The status reports inspection, owner availability, or a blocked start; a route marker or waypoint must lie directly below the Autopilot sensor after excluding the craft itself.

Waypoints configure automatic departure, a delay in game ticks (20 ticks per second), optional output channels, and a direct departure signal to the visiting vehicle. Disable automatic departure to wait for another activation. Output channels pulse on departure; direct signaling lets the vehicle depart without matching channel assignments. An unoccupied waypoint has no ticker or route scan. Returning to a previously visited marker does not finish a journey: a connected loop keeps running. For continuous laps through waypoints, enable automatic departure and direct signaling at those stops; manual stops continue to wait for another pulse.

Each waypoint can select Block, Taxi, or Hover as its stopped mode and Taxi or Hover for departure. Hover height is adjustable from 0 to 16 blocks, measured from the waypoint's top to the Autopilot sensor. The vehicle's hull and landing gear may extend below that height; mount the controller on the bottom of the craft and allow clearance for those parts. The controller detects route markers up to 16 blocks below it, matching the maximum waypoint hover height. Hover requires the usual propulsion and lift blocks. Block parking and departure retain protection checks and require the vehicle owner to be online in the same dimension; blocked departures remain parked and retry.

Choose **Vehicle Status** in a programmable screen or console/input surface picker to display hover clearance and autopilot status. Click the autopilot row to toggle navigation, or **Next >** to activate it and leave the current waypoint without switching it off first. Next also schedules departure when the vehicle is parked as blocks. The side-by-side **Block**, **Taxi**, and **Hover** buttons select the vehicle mode; the active mode is highlighted. Mode changes require a Vehicle Controller and retain normal permission, propulsion, landing gear, clearance, and parking checks. Select Taxi before restoring a hovering craft as blocks. These controls also fit half-height input and console surfaces.

The Vehicle Controller dialog contains separate optional Park, Taxi, and Hover channel fields; rising power selects that mode. The button beside each field switches modes immediately.
