# Programmable Door rendering in 1.5

Controlled fixtures identified repeated tile-renderer submission as a useful optimization
target. For 64 complete doors with shaders disabled, median render-thread CPU work was
3.443 ms for MrCrayfish’s Furniture Mod sliding doors, 0.597 ms for Malisis iron doors, 0.605 ms for
Vandor Labs 1.4 default Programmable Doors, and 0.370 ms for its sliding doors.
The corresponding Java draw submissions were 128, 1, 192 and 128.
These are isolated fixture costs, not frame times for a populated world or predicted FPS.

Malisis demonstrates the benefit of sharing a tile-renderer buffer. Merely extending
FastTESR does not enable batching: the tile must opt in, and the renderer must emit into
the supplied buffer without changing GL state. Decocraft's retained geometry also shows
why a model's node count alone does not establish its recurring CPU cost.

Version 1.5 prepares compatible opaque door geometry once per cached model. It transforms
those vertices on the CPU into Forge's shared buffer, preserving vertex colors, UVs and
live lightmaps. Geometry caches remain bounded and clear on resource reload. Glass,
custom face textures, OptiFine, unknown item renderers and incompatible model formats
retain the existing renderer. CodeChickenLib's wrapper is accepted only when its parent
is the vanilla item renderer. Large doors render only from their anchor.

Non-rendering checks compare the emitted positions against the existing renderer's
matrix operations for all four facings, normal and large leaves, swing and sliding poses,
and both lightmap conventions. This checks geometry and submission data; it does not
establish shader appearance or a measured 1.5 speedup. Numerical before/after speedup
claims and Complementary Unbound visual acceptance remain unverified.

Potential future improvements include consolidating byte-identical artwork while
preserving resource-pack overrides and reducing atlas padding for rectangular textures.
Neither atlas change is included in 1.5. Baking settled animated leaves into terrain
would require testing the tradeoff between recurring frame cost and transition rebuilds.
