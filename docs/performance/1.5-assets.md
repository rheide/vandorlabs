# Version 1.5 runtime assets

The standard JAR falls from **53.46 MiB to 25.10 MiB**, a reduction of about
**53%**, after dropping the old High artwork tier, removing duplicate door
images, resizing imported hatches and inventory textures, and sharing model
geometry. These are archive sizes, not measurements of FPS or GPU memory.

| Current contents | Compressed payload |
| --- | ---: |
| Static PNGs, including animation previews | 11.50 MiB |
| Animation frame data | 4.92 MiB |
| JSON models | 2.98 MiB |
| Java classes | 1.23 MiB |
| Other resources | 0.79 MiB |
| ZIP directory/header overhead | 3.70 MiB |

Static artwork remains the largest category. The 109 animation resources are
unchanged: 77 contain 128×128 frames and 32 contain 128×64 frames, with six frames
per animation. Their static preview PNGs are counted in the static-art category.

## Texture resolutions

- Door leaf artwork: **128×256 Small**, **256×512 Large**.
- Complete Double Doors artwork: **256×256 Small**, **512×512 Large**.
- Imported hatch artwork: **128×128 Small**, **256×256 Large**.
- Programmable Glass pane/frame artwork: **256×256 Small**, **512×512 Large**.
- Standard inventory texture images: **128×128**. Generated door icons retain
  model geometry and slot padding; changing PNG size does not replace their
  inventory transforms.
- Other artwork retains its existing role-specific resolutions, including
  16×16 structural materials, 64×64 fixtures, and 128×128 or 128×64 screens.
  Existing auxiliary images also include 2×2, 4×4, 32×32, 140×140, 240×240 and
  480×480 sizes; these were not part of the removed door tier.

The former Medium artwork becomes Large. Former Large door selections,
replacement-face texture IDs and Programmable Glass settings resolve to the
new Large tier. Saved designs, tint, joining and physical opening sizes remain
supported. Removed runtime images have no remaining packaged model references.

## Why there were so many models

The generators cover combinations of artwork, resolution, framing, pairing,
left/right handedness, fixed/leaf/glass parts, motion and hinge visibility.
Many files differed only in texture bindings, while repeating the same element
bounds, faces, UVs and inventory transforms. ZIP compresses each file separately,
so this repeated geometry still occupied substantial space.

The packaged model count falls from **16,200 to 12,628**, including **205 shared
geometry templates**. Removing the old High tier eliminates 3,620 source model
files. Of the retained files, 3,786 models now inherit their geometry from those
templates while keeping their original resource names and texture bindings.
Compressed model payload falls from approximately **6.15 MiB to 2.98 MiB**.

Before texture pruning, staged JSON content falls from 64,965,811 to 11,006,501
bytes. Minification and parent inheritance reduce archive and parsing input;
they do not by themselves reduce the number of Minecraft baked model variants
or guarantee lower render times. Further variant reduction would require a
runtime model loader and changes to legacy item/model registration. That larger
change is unnecessary for the current archive savings.

## Validation

The normal build checks every retained source JSON model against its packaged
form after expanding shared parents and applying the explicit migration/pruning
rules. The comparison includes geometry, UVs, shade flags, transforms and
texture bindings. It also verifies model and blockstate references, packaged
image dimensions, missing High-tier resources, legacy texture aliases, and
matching reflection patterns across glass sizes.

CPU-only Forge checks cover old door and glass NBT/metadata migration,
Small/Large hatch selection, and shared Screens/Controls row selection and
Bare/Framed variants. Optional component-provider checks cover Malisis-style
upper/lower door icons and provider fallback behavior. A focused shader-free Forge client run also checks initialized dialog layouts at
320×240 and taller GUI sizes, captures the screen/input/console controls, and
exercises filesystem texture previews and legacy migration in the integrated
world. The half-input and half-console captures show separate full-width Framed
and Redstone Input rows. Software rendering is used for this GUI validation;
hardware-driver testing, shader appearance and Malisis in-game appearance remain
unverified.
